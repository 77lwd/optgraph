### 3. 架构亮点

#### 双重内存存储
```python
class MemoryState(MessagesState):
    summary: str           # 语义摘要（LLM 生成，可有损）
    user_profile: dict     # 结构化画像（确定性提取，永不丢失）
    messages: List         # 最近对话
```

#### 假对话注入（解决 DeepSeek SystemMessage 问题）
```python
# DeepSeek 忽略 SystemMessage，所以我们注入假对话：
HumanMessage("Hi! my name is Alice, I live in Beijing...")
AIMessage("Got it! I'll remember that.")
# 开销：仅 1.4% 额外 tokens
```

#### 官方 API 使用
```python
# 使用 LangGraph 推荐的 RemoveMessage API
delete_messages = [RemoveMessage(id=m.id) for m in old_messages]
return {"messages": delete_messages}
```

## ⚠️ 已知限制与未来改进

### 当前限制

1. **用户画像更新**
   - 问题：用户说"我搬到上海了"，画像不会自动更新
   - 影响：中等（摘要会记录，但结构化字段不更新）
   - 优先级：P1

2. **画像提取精度**
   - 问题：使用简单正则，可能错过复杂介绍
   - 影响：低（测试显示大部分场景工作良好）
   - 优先级：P2

3. **摘要质量退化**
   - 问题：多次压缩后摘要可能退化
   - 缓解：已有安全检查（max_tokens、长度验证）
   - 影响：低（50 轮测试显示质量稳定）
   - 优先级：P3

### 未来增强

#### Phase 3: 外部内存（P1）
- 集成 Mem0 或向量数据库
- 跨会话长期记忆
- 基于语义的检索

#### Phase 4: 智能画像（P2）
- NER（命名实体识别）
- LLM 驱动的画像更新检测
- 实体关系图

#### Phase 5: 自适应压缩（P3）
- 根据对话重要性动态调整 `keep_recent`
- 主题建模
- 多层压缩策略

1. DeepSeek 不支持 SystemMessage（需要测试验证）
2. 摘要生成需要安全检查（防止退化）
